# Visual Concept Kit 1.1.0

Turn an inspected concept image and structured design choices into a portable direction sheet, editable brief and hash manifest. It preserves a verified parent when making a controlled variation. This adds repeatable output, input checks, tamper detection and continuity to the image-making process.

**Supported execution:** Python 3.10+ in an authorized OpenAI Codex workflow supporting a ChatGPT dot. Browser: view the finished HTML. Image generation/editing requires the host's supported image tool and the user's existing authorized access. The renderer itself is offline and makes no API calls. Downloading this folder does not install a ChatGPT skill or launch a task.

## Try the saved example

From the repository root:

```sh
python3 tools/visual-concept-kit/kit.py reopen creations/quiet-listening-room/original
```

Open `creations/quiet-listening-room/original/sheet.html`. Save/copy the whole folder to reopen it elsewhere; the image, CSS, briefs and manifest travel together. The JSON brief is editable in any text editor. Browser Print can save a PDF; PDF export is a browser action, not generated by this script.

## Make a version with your dot and Codex

1. Select a saved creation and download or clone the public source. Keep its credit and license files.
2. Tell your dot the desired outcome and choose one element to change. Use the actual host's attachment/file flow to hand the folder to Codex. Confirm the writable output destination through that host. Do not paste commands into an unsupported browser transport.
3. Use the host's image editor on the selected concept image. Lock the camera, objects, materials and lighting; change only chair upholstery in this release. Save the returned PNG. Inspect it visually; code cannot verify semantic fidelity.
4. Copy `brief.json`, change only `chair_upholstery`, and run:

```sh
python3 tools/visual-concept-kit/kit.py build my-brief.json --image edited-chair.png --out my-version --parent creations/quiet-listening-room/original --change chair_upholstery
python3 tools/visual-concept-kit/kit.py reopen my-version
```

5. Inspect `my-version/sheet.html`, save the whole folder, close and reopen it. Submit only the intended public output through [the contribution guide](../../CONTRIBUTING.md#creation-and-remix-exchange). The original remains intact. Compare the actual images before claiming that unrequested details were preserved.

For a new project, edit the full brief and omit `--parent` / `--change`. This renderer currently supports one named controlled change, chair upholstery. Other adaptation types require a reviewed contract change; do not remove the continuity checks to force them through.

## Recovery

- Missing image tool: use the saved sample or provide an image you have rights to use; report generation as unavailable. Never label a prepared prompt as an executed image.
- Missing Python: view the existing sheet and edit the brief; execution remains blocked until a supported host is available.
- Missing/tampered files: `reopen` fails. Restore the original folder from source; never silently bless changed bytes.
- Existing output directory: build refuses to overwrite it. Choose a new directory.
- Wrong brief or extra changes: fix the brief or create a new independent direction. A controlled remix must have exactly the named change and a different image hash.
- Input text is data, escaped into HTML. No network access, account changes, file watching or automatic publication. Hashes establish exact bytes, not authorship, owner approval or design quality.

License: repository LICENSE and NOTICE. Image provenance and exact generation/edit prompts are in the creation's `PROCESS.md`; generated concepts are design hypotheses, not physical or acoustic specifications.

## 1.1 metadata and review integrity

New briefs require image_description: a truthful description of the selected image without hardcoded example content. The renderer validates and escapes it as the complete image alt text. The optional literal token {chair_upholstery} substitutes the validated selected color name; unrelated descriptions receive no hardcoded room or chair text. Width/height come from validated PNG IHDR dimensions, including its CRC and bounded dimensions. This validates metadata, not every compressed image pixel. The renderer does not generate or edit images; those steps require the actual supported host image tool and visual inspection.

Legacy 1.0 folders can still be hash-reopened. A controlled 1.1 variation needs a 1.1 parent; create a new migrated direction with the original credit before varying it. Old artifacts remain in Git history.

Public exchange acceptance uses the full declared package (manifest, linked image/CSS/briefs, process, run evidence, license/notices and tool source). Any covered byte or submission metadata change invalidates the prior review and requires renewed review. Hashes bind content; they do not authenticate a reviewer or grant publication authority.
